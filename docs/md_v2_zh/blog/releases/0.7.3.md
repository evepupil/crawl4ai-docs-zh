## 🎨 多URL配置：因URL而异

**问题场景**：您需要爬取文档站点、博客和API端点的混合内容。每种内容需要不同处理方式——文档需要缓存、新闻需要最新内容、API需要结构化提取。此前您需要运行单独爬取任务或编写复杂条件逻辑。

**解决方案**：实现了URL专属配置，允许您在单次爬取批次中为不同URL模式定义不同策略。采用首次匹配原则，并支持可选回退机制。

### 技术实现

```python
from crawl4ai import AsyncWebCrawler, CrawlerRunConfig, MatchMode

# 为不同类型内容定义专属配置
configs = [
    # 文档站点 - 激进缓存，包含链接
    CrawlerRunConfig(
        url_matcher=["*docs*", "*documentation*"],
        cache_mode="write",
        markdown_generator_options={"include_links": True}
    ),
    
    # 新闻/博客站点 - 新鲜内容，滚动加载延迟内容
    CrawlerRunConfig(
        url_matcher=lambda url: 'blog' in url or 'news' in url,
        cache_mode="bypass",
        js_code="window.scrollTo(0, document.body.scrollHeight/2);"
    ),
    
    # API端点 - 结构化提取
    CrawlerRunConfig(
        url_matcher=["*.json", "*api*"],
        extraction_strategy=LLMExtractionStrategy(
            provider="openai/gpt-4o-mini",
            extraction_type="structured"
        )
    ),
    
    # 其他所有情况的默认回退
    CrawlerRunConfig()  # 无url_matcher = 匹配所有
]

# 使用适当配置爬取多个URL
async with AsyncWebCrawler() as crawler:
    results = await crawler.arun_many(
        urls=[
            "https://docs.python.org/3/",      # → 使用文档配置
            "https://blog.python.org/",        # → 使用博客配置  
            "https://api.github.com/users",    # → 使用API配置
            "https://example.com/"             # → 使用默认配置
        ],
        config=configs
    )
```

**匹配能力：**
- **字符串模式**：通配符如`"*.pdf"`、`"*/blog/*"`
- **函数匹配器**：Lambda函数实现复杂逻辑
- **混合匹配器**：字符串和函数与AND/OR逻辑组合
- **回退支持**：无匹配时使用默认配置

**预期实际影响：**
- **混合内容站点**：单次爬取处理博客、文档和下载
- **多域名爬取**：不同域名采用不同策略而无需单独运行
- **降低复杂度**：无需在提取代码中编写if/else森林
- **更好性能**：每个URL获得精确所需的处理

## 🐳 Docker：灵活的LLM提供商配置

**问题场景**：Docker部署中LLM提供商硬编码。想从OpenAI切换到Groq？需要重建并重新部署。测试不同模型？需要多个Docker镜像。

**解决方案**：通过环境变量配置LLM提供商。无需修改代码或重建镜像即可切换提供商。

### 部署灵活性

```bash
# 选项1：直接环境变量
docker run -d \
  -e LLM_PROVIDER="groq/llama-3.2-3b-preview" \
  -e GROQ_API_KEY="your-key" \
  -p 11235:11235 \
  unclecode/crawl4ai:latest

# 选项2：使用.llm.env文件（生产环境推荐）
# 创建.llm.env文件：
# LLM_PROVIDER=openai/gpt-4o-mini
# OPENAI_API_KEY=your-openai-key
# GROQ_API_KEY=your-groq-key

docker run -d \
  --env-file .llm.env \
  -p 11235:11235 \
  unclecode/crawl4ai:latest
```

需要时可按请求覆盖：
```python
# 使用.llm.env中的默认提供商
response = requests.post("http://localhost:11235/crawl", json={
    "url": "https://example.com",
    "extraction_strategy": {"type": "llm"}
})

# 为特定请求覆盖使用不同提供商
response = requests.post("http://localhost:11235/crawl", json={
    "url": "https://complex-page.com",
    "extraction_strategy": {
        "type": "llm",
        "provider": "openai/gpt-4"  # 覆盖默认
    }
})
```

**预期实际影响：**
- **成本优化**：简单任务使用廉价模型，复杂任务使用高级模型
- **A/B测试**：无需部署变更即可比较提供商性能
- **回退策略**：在中断时动态切换提供商
- **开发灵活性**：本地测试使用一个提供商，部署使用另一个
- **安全配置**：API密钥保存在`.llm.env`文件中而非命令中
