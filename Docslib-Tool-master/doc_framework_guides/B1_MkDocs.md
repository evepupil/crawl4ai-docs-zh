# MkDocs文档翻译指南

## 文件翻译范围

MkDocs是一个静态站点生成器，主要翻译内容包括：

1. **Markdown文件**：
   - 位于`docs/`目录下的所有`.md`文件
   - 文件内的所有文本内容，包括标题、段落、列表、表格等
   - 代码块内的注释（可选）

2. **配置文件**：
   - `mkdocs.yml`中的站点名称、导航菜单、页面标题等配置项

3. **主题自定义内容**：
   - 自定义主题中的模板文件（通常位于`theme/`目录）
   - 自定义CSS中的注释

## 部署步骤

### 准备工作

1. 克隆原始文档仓库
```bash
git clone https://github.com/原始项目/文档仓库.git
cd 文档仓库
```

2. 安装MkDocs和相关依赖
```bash
pip install mkdocs
pip install -r requirements.txt  # 如果有额外依赖
```

### 翻译流程

1. 创建翻译分支
```bash
git checkout -b translation-zh
```

2. 翻译`docs/`目录下的Markdown文件
3. 更新`mkdocs.yml`中的配置（站点名称、导航结构等）
4. 翻译自定义主题文件（如果有）

### 构建与测试

1. 本地预览翻译效果
```bash
mkdocs serve
```

2. 构建静态站点
```bash
mkdocs build
```

3. 检查生成的`site/`目录中的HTML文件是否正确显示翻译内容

### 部署方法

1. **GitHub Pages部署**
```bash
mkdocs gh-deploy
```

2. **自定义服务器部署**
   - 将生成的`site/`目录上传到Web服务器
   - 配置服务器以提供静态文件服务

## 注意事项

1. **保持格式一致**：翻译时保持原始Markdown格式，不要改变标题层级、列表结构等
2. **保留原始链接**：内部链接需要保持不变，除非目标文件名也被翻译
3. **代码示例**：通常不翻译代码块中的代码，但可以翻译代码中的注释
4. **图片处理**：
   - 如果图片包含文本，考虑创建本地化版本
   - 图片路径需要保持不变或相应调整
5. **配置文件注意**：修改`mkdocs.yml`时需谨慎，错误的配置可能导致构建失败
6. **多语言支持**：
   - 可以使用`mkdocs-static-i18n`插件实现多语言支持
   - 或创建单独的语言分支/仓库

## 自动化工具建议

1. 使用翻译记忆工具保持术语一致性
2. 考虑使用脚本批量处理Markdown文件
3. 建立术语表，确保专业术语翻译统一

## 维护更新

1. 定期与原始仓库同步，合并上游更改
2. 使用diff工具识别需要更新翻译的部分
3. 建立自动化流程监测原始文档的变化
